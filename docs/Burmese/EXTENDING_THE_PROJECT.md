# Extending the Project (မြန်မာ)

Capstone စီမံကိန်းများ၊ အဆင့်မြင့် လေ့လာသင်ယူမှုများ သို့မဟုတ် လုပ်ငန်းသုံးအဆင့် မြှင့်တင်မှုများအတွက် အကြံပြုချက်များ ဖြစ်သည်။ အကြံပြုချက် တစ်ခုစီတွင် သင်ကြားပေးမည့် သဘောတရား၊ လုပ်ဆောင်ရမည့် အတိုင်းအတာနှင့် အကောင်အထည်ဖော်ရန် အကြံပြုထားသော အဆင့်များကို ထည့်သွင်းဖော်ပြထားသည်။

---

# Extending the Project (အင်္ဂလိပ် အညွှန်း)

---

## ခက်ခဲမှု အဆင့် သတ်မှတ်ချက် (Difficulty Legend)

* **Easy** - ၁ ရက်မှ ၂ ရက်အတွင်း ပြီးစီးနိုင်သည်။ အခြေခံများကို လေ့ကျင့်ရန် သင့်တော်သည်။
* **Medium** - ၃ ရက်မှ ၅ ရက်။ အစိတ်အပိုင်း အများအပြားကို နားလည်ထားရန် လိုအပ်သည်။
* **Hard** - ၁ ပတ် သို့မဟုတ် ထို့ထက်ပိုသည်။ ဒီဇိုင်းရေးဆွဲခြင်းနှင့် တည်ဆောက်ခြင်း အမြောက်အမြား ပါဝင်သည်။

---

## အေးဂျင့်နှင့် Tools စနစ် (Agent and Tooling)

### Code Formatter Tool တစ်ခု ပေါင်းထည့်ခြင်း (Add a Code Formatter Tool)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - Tool ရေးဆွဲထုတ်လုပ်ခြင်း

ရွေးချယ်ထားသော ဖိုင်များပေါ်တွင် Prettier သို့မဟုတ် Biome ကို Run ပေးသည့် Tool တစ်ခု ပေါင်းထည့်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `src/tools/index.ts` ထဲတွင် Tool သတ်မှတ်ချက် အသစ်တစ်ခု ပေါင်းထည့်ပါ။
2. ဖိုင်လမ်းကြောင်း Input ကို စစ်ဆေးအတည်ပြုရန် Zod ကို အသုံးပြုပါ။
3. `run_bash` မှတစ်ဆင့် `prettier --write <file>` ကို Run ပါ။
4. ပြန်လည်စစ်ဆေးနိုင်ရန် ကွာခြားချက် (diff) များကို အသုံးပြုသူထံ ပြသပါ။

### Git Branch Manager တစ်ခု ပေါင်းထည့်ခြင်း (Add a Git Branch Manager)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Git အလိုအလျောက် လုပ်ဆောင်မှု

Git branches များကို ဖန်တီးခြင်း၊ ပြောင်းလဲခြင်းနှင့် ပေါင်းစည်းခြင်းတို့အတွက် Tools များကို ပေါင်းထည့်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `create_branch`၊ `switch_branch`၊ `merge_branch` tools များကို ပေါင်းထည့်ပါ။
2. Branch အမည်များကို Zod ဖြင့် စစ်ဆေးပါ။
3. `run_bash` မှတစ်ဆင့် Git commands များကို Run ပါ။
4. Branch အခြေအနေကို TUI တွင် ပြသပါ။

### Database Query Tool တစ်ခု ပေါင်းထည့်ခြင်း (Add a Database Query Tool)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - ပြင်ပ ဝန်ဆောင်မှု ချိတ်ဆက်ခြင်း

အေးဂျင့်အား Database သို့ တိုက်ရိုက် Query မေးမြန်းခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. ချိတ်ဆက်မှု ပြင်ဆင်ချက် ပါဝင်သော `query_database` tool တစ်ခုကို ပေါင်းထည့်ပါ။
2. Injection မှ ကာကွယ်ရန် SQL queries များကို စစ်ဆေးပါ။
3. ရလဒ်များကို ဇယားပုံစံတကျ ပြန်လည် ပေးပို့ပါ။
4. ဖတ်ရှုခွင့်သက်သက် (Read-only) ဖြစ်စေရန် ခွင့်ပြုချက် အကာအကွယ် ပေါင်းထည့်ပါ။

---

## LLM နှင့် တုံ့ပြန်ချက် ထုတ်လုပ်ခြင်း (LLM and Generation)

### Multi-Modal စနစ် ထောက်ပံ့မှု ပေါင်းထည့်ခြင်း (Add Multi-Modal Support - Images)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Multi-modal LLM

အေးဂျင့်အား ရုပ်ပုံများကို Vision စွမ်းရည်ပါရှိသော Models များထံ ပေးပို့၍ လေ့လာသုံးသပ်နိုင်စွမ်း ရရှိစေပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. လက်ရှိ Model က Vision ကို ထောက်ပံ့မှု ရှိမရှိ စစ်ဆေးပါ။
2. ရုပ်ပုံလမ်းကြောင်း သို့မဟုတ် URLs များကို လက်ခံနိုင်သည့် `analyze_image` tool တစ်ခု ပေါင်းထည့်ပါ။
3. ရုပ်ပုံများကို Base64 အဖြစ် ပြောင်းလဲပြီး LLM request ထဲတွင် ထည့်သွင်းပါ။
4. LLM ၏ ရုပ်ပုံ သုံးသပ်ချက်ကို TUI တွင် ပြသပါ။

### Streaming Artifacts ပေါင်းထည့်ခြင်း (Add Streaming Artifacts)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - ပိုမိုကြွယ်ဝသော တုံ့ပြန်ချက် ရလဒ်များ

အေးဂျင့်အား စာသားများ ပေးပို့နေစဉ်အတွင်း အဆင့်မြင့် ရလဒ်များ (Code blocks၊ Diagrams၊ Tables) ကို ထုတ်လုပ်ခွင့် ပေးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. တိုက်ရိုက် ထွက်ပေါ်လာသော တုံ့ပြန်ချက်များထဲရှိ Artifact markers များကို စစ်ဆေးပါ။
2. TUI တွင် Code blocks များကို အရောင်မွမ်းမံမှုများ (Syntax highlighting) ဖြင့် ပုံဖော်ပေးပါ။
3. Code artifacts များကို ကူးယူနိုင်ရန် Copy-to-clipboard ခလုတ်များ ပေါင်းထည့်ပါ။

### Model အစားထိုး အသုံးပြုမှု စနစ် ပေါင်းထည့်ခြင်း (Add Model Fallback Chains)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - စနစ်၏ ကြံ့ခိုင်မှု

Provider တစ်ခုခု အလုပ်မလုပ်တော့ပါက သို့မဟုတ် Rate limit မိသွားပါက အလိုအလျောက် အစားထိုး အသုံးပြုမည့် စနစ်ကို ပြင်ဆင်သတ်မှတ်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. အသုံးပြုသူ သတ်မှတ်ထားသော Fallback chains များကို ထောက်ပံ့နိုင်စေရန် `src/llm/fallback.ts` ကို တိုးချဲ့ပါ။
2. Fallback အစီအစဉ်အတွက် CLI/Config အပိုဆောင်း ပြင်ဆင်ချက်များ ပေါင်းထည့်ပါ။
3. စစ်ဆေးပြင်ဆင်နိုင်ရန် Fallback ဖြစ်ရပ်များကို မှတ်တမ်းတင် (Log) ပါ။

## သတင်းအချက်အလက် ရယူခြင်းနှင့် Context စီမံမှု (Retrieval and Context)

### အေးဂျင့်တွင် RAG စနစ် ပေါင်းထည့်ခြင်း (Add RAG to the Agent)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - မှတ်တမ်းအချက်အလက် အခြေပြု Coding

အေးဂျင့်အား မဖြေကြားမီ RAG ကို အသုံးပြု၍ သင်၏ အချက်အလက် မှတ်တမ်းများ သို့မဟုတ် Codebase ကို ရှာဖွေခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. သင်၏ Project မှ စာရွက်စာတမ်းများနှင့် Source code များကို Vector store ထဲသို့ Index လုပ်ပါ။
2. Hybrid search ပြုလုပ်နိုင်သော `search_codebase` tool တစ်ခု ပေါင်းထည့်ပါ။
3. LLM မခေါ်ယူမီ ရရှိလာသော ရလဒ်များကို အေးဂျင့်၏ Context ထဲသို့ ထည့်သွင်းပေးပါ။
4. RAG ပါဝင်မှုရှိသော/မရှိသော အဖြေများ၏ အရည်အသွေးကို နှိုင်းယှဉ်ပါ။

### စကားပြောမှတ်တမ်း အနှစ်ချုပ် စနစ် ပေါင်းထည့်ခြင်း (Add Conversation Memory Summaries)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Context အမြောက်အမြား စီမံခန့်ခွဲခြင်း

Context မပျောက်ပျက်စေဘဲ Tokens ပမာဏကို ချွေတာရန် ရှေးယခင် စကားပြော မှတ်တမ်းများကို အနှစ်ချုပ်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `src/session/` ထဲတွင် စကားပြော မှတ်တမ်း ပမာဏ သတ်မှတ်ချက် ထက် ကျော်လွန်သွားချိန်ကို စစ်ဆေးပါ။
2. စကားပြော မှတ်တမ်းဟောင်းများကို အနှစ်ချုပ်ရန် LLM ကို ခေါ်ယူပါ။
3. အနှစ်ချုပ်ကို System prompt ၏ ထိပ်တွင် ပေါင်းထည့်ပါ။
4. Token အသုံးပြုမှုနှင့် အဖြေ၏ အရည်အသွေးကို နှိုင်းယှဉ်ပါ။

## ရုပ်ထွက်နှင့် အသုံးပြုသူ အတွေ့အကြုံ (UI and UX)

### Diff Viewer တစ်ခု ပေါင်းထည့်ခြင်း (Add a Diff Viewer)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - ရုပ်မြင်သံကြား Code စစ်ဆေးမှု

ဖိုင်ပြင်ဆင်ချက်များကို TUI တွင် ယှဉ်တွဲပြသသော Diff ပုံစံဖြင့် ပြသပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `src/ui/App.tsx` သို့ `diff` view တစ်ခု ပေါင်းထည့်ပါ။
2. စာကြောင်းတစ်ကြောင်းစီ၏ အပြောင်းအလဲများကို တွက်ချက်ရန် Diff library တစ်ခုကို အသုံးပြုပါ။
3. ပေါင်းထည့်လိုက်သော/ဖျက်ထုတ်လိုက်သော စာကြောင်းများကို အရောင်ဖြင့် ပုံဖော်ပေးပါ။
4. လက်ခံမည်/မူလအတိုင်း ပြန်ထားမည် (Accept/Revert) ခလုတ်များ ပေါင်းထည့်ပါ။

### အသံဖြင့် အမိန့်ပေးသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Voice Input)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - Multi-modal Input

TUI တွင် အသံဖြင့် အမိန့်ပေးနိုင်ရန် မိုက်ခရိုဖုန်းကို အသုံးပြုပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. စနစ်၏ မိုက်ခရိုဖုန်းကို အသုံးပြု၍ အသံကို ဖမ်းယူပါ။
2. Local သို့မဟုတ် Cloud STT ဝန်ဆောင်မှုဖြင့် စာသားအဖြစ် ပြောင်းလဲပါ။
3. ပြောင်းလဲလိုက်သော စာသားကို ပြသပြီး မေးခွန်းအဖြစ် ပေးပို့ပါ။
4. ဖိထားစဉ် ပြောဆိုနိုင်သည့် (Push-to-talk) ခလုတ် Shortcut တစ်ခု ပေါင်းထည့်ပါ။

### မျက်နှာပြင် ခွဲခြားပြသသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Split Panes)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - အဆင့်မြင့် TUI Layout

Code နှင့် အေးဂျင့်၏ တုံ့ပြန်ချက်များကို ဘေးချင်းယှဉ် ပြသပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Ink flexbox layout ကို အသုံးပြုနိုင်ရန် `src/ui/App.tsx` ကို ပြင်ဆင်ပါ။
2. ဘယ်ဘက်မျက်နှာပြင် - File viewer
3. ညာဘက်မျက်နှာပြင် - Agent chat
4. မျက်နှာပြင်များအကြား ပြောင်းလဲနိုင်ရန် ကီးဘုတ် Shortcuts များ ပေါင်းထည့်ပါ။

## ပူးပေါင်းဆောင်ရွက်ခြင်း (Collaboration)

### Real-Time Code မျှဝေမှု စနစ် ပေါင်းထည့်ခြင်း (Add Real-Time Code Sharing)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - ပူးတွဲ ပြင်ဆင်ရေးသားခြင်း

အသုံးပြုသူ အများအပြားကို ဖိုင်တစ်ခုတည်းအား တစ်ပြိုင်နက်တည်း ပြင်ဆင်ခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. CRDT အခြေပြု ပဋိပက္ခဖြေရှင်းရေး စနစ်ဖြင့် `src/shared-sessions/` ကို တိုးချဲ့ပါ။
2. ဖိုင်အပြောင်းအလဲများကို Session တွင် ပါဝင်သူအားလုံးထံ လွှင့်ထုတ်ပေးပါ။
3. အခြားသူများ၏ Cursors များနှင့် ရွေးချယ်ထားမှုများကို TUI တွင် ပြသပါ။
4. Offline စင့်ခ်လုပ်မှုနှင့် ပေါင်းစည်းမှုများကို စီမံပါ။

### Session မှတ်တမ်းတင်ခြင်းနှင့် ပြန်လည်ပြသခြင်း စနစ် ပေါင်းထည့်ခြင်း (Add Session Recording and Playback)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Session ပြန်လည်ကြည့်ရှုခြင်း

စစ်ဆေးပြင်ဆင်ရန် သို့မဟုတ် လေ့ကျင့်ရန်အတွက် အေးဂျင့်၏ Sessions များကို မှတ်တမ်းတင်ပြီး ပြန်လည်ပြသခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Tool ခေါ်ယူမှုများ၊ LLM တုံ့ပြန်ချက်များနှင့် အသုံးပြုသူ Input အားလုံးကို မှတ်တမ်းတင်ပါ။
2. မှတ်တမ်းများကို ပြန်လည်ပြသနိုင်သော Format (JSON) ဖြင့် သိမ်းဆည်းပါ။
3. Session ကို အဆင့်လိုက် ပြန်လည်ပြသပေးသည့် `play` command တစ်ခု ပေါင်းထည့်ပါ။
4. အမြန်နှုန်း ထိန်းချုပ်မှုနှင့် အပိုင်းလိုက် ရွှေ့ဆိုင်းမှုများကို ထောက်ပံ့ပေးပါ။

## အခြေခံ အဆောက်အအုံ (Infrastructure)

### Full Stack အတွက် Docker Compose ပေါင်းထည့်ခြင်း (Add Docker Compose for Full Stack)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - တပ်ဆင်အသုံးပြုခြင်း

TUI၊ Daemon နှင့် လိုအပ်သော မှီခိုမှုများကို Run ပေးသည့် `docker-compose.yml` တစ်ခု ဖန်တီးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. CLI အတွက် `Dockerfile` တစ်ခု ရေးသားပါ။
2. CLI ဝန်ဆောင်မှုပါဝင်သော `docker-compose.yml` တစ်ခု ရေးသားပါ။
3. Environment variables စီမံခန့်ခွဲမှုကို ပေါင်းထည့်ပါ။
4. သန့်ရှင်းသော စက်တစ်ခုပေါ်တွင် စမ်းသပ်ပါ။

### Plugin Marketplace ပေါင်းထည့်ခြင်း (Add Plugin Marketplace)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - ဖြန့်ဖြူးခြင်း

အသုံးပြုသူများအား ပြင်ပ Registry မှ Plugins များကို တပ်ဆင်ခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Plugin manifest format တစ်ခု သတ်မှတ်ပါ။
2. Registry API တစ်ခု တည်ဆောက်ပါ။
3. `mtc plugin install <name>` နှင့် `mtc plugin search <query>` များကို ပေါင်းထည့်ပါ။
4. Plugin စစ်ဆေးခြင်းနှင့် အတည်ပြုခြင်းများကို ထည့်သွင်းဆောင်ရွက်ပါ။

### စနစ် စောင့်ကြည့်လေ့လာရေး Dashboard ပေါင်းထည့်ခြင်း (Add Observability Dashboard)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - စောင့်ကြည့်စစ်ဆေးခြင်း

အေးဂျင့် အသုံးပြုမှု၊ Token သုံးစွဲမှုနှင့် အမှားအယွင်း ဖြစ်ပွားမှုနှုန်းများကို ပြသသည့် Dashboard တစ်ခု တည်ဆောက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. အေးဂျင့် Loop တွင် တိုင်းတာမှု ကိန်းဂဏန်းများ ထည့်သွင်းပါ။
2. တိုင်းတာချက်များကို SQLite တွင် သိမ်းဆည်းပါ သို့မဟုတ် Prometheus သို့ ပေးပို့ပါ။
3. Web dashboard တစ်ခု တည်ဆောက်ပါ။
4. အမှားအယွင်း ပမာဏ များပြားခြင်း သို့မဟုတ် ပုံမှန်မဟုတ်သော အသုံးပြုမှုများအတွက် အကြောင်းကြားချက်များ ပေါင်းထည့်ပါ။

## လုံခြုံရေး (Security)

### Prompt Injection စစ်ဆေးသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Prompt Injection Detection)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - လုံခြုံရေး

LLM ထံ မရောက်ရှိမီ Prompt injection ကြိုးပမ်းမှုများကို စစ်ဆေး၍ တားဆီးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Injection ပုံစံများကို စစ်ဆေးသည့် Input classifier တစ်ခု ပေါင်းထည့်ပါ။
2. အတွေ့အများဆုံး ပုံစံများ - "ignore previous instructions", "you are now DAN"
3. စစ်ဆေးတွေ့ရှိရသော Injections များအတွက် ဘေးကင်းသော အစားထိုး မက်ဆေ့ဂျ်တစ်ခု ပြန်လည်ပေးပို့ပါ။
4. လုံခြုံရေးအရ စစ်ဆေးနိုင်ရန် ကြိုးပမ်းမှုများကို မှတ်တမ်းတင်ပါ။

### ဖိုင်ပြင်ဆင်မှုများတွင် လျှို့ဝှက်ချက်များကို စစ်ဆေးသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Secret Scanning in Edits)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - လုံခြုံရေး

မသိလိုက်ဘဲ ပါဝင်သွားသော လျှို့ဝှက်ချက်များကို မသိမ်းဆည်းမီ ဖိုင်ပြင်ဆင်ချက်များထဲတွင် ရှာဖွေစစ်ဆေးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. ပြင်ဆင်ထားသော အကြောင်းအရာများကို စစ်ဆေးရန် `src/secrets/` ကို တိုးချဲ့ပါ။
2. အတွေ့များသော လျှို့ဝှက်ချက် ပုံစံများကို တိုက်ဆိုင်စစ်ဆေးပါ (API keys, tokens, passwords)။
3. မသိမ်းဆည်းမီ အသုံးပြုသူအား သတိပေးပါ။
4. ကျော်လွန်ဆောင်ရွက်နိုင်ရန် `--force` flag တစ်ခု ပေါင်းထည့်ပါ။

## အကဲဖြတ်ခြင်းနှင့် စမ်းသပ်ခြင်း (Evaluation and Testing)

### Tool တိကျမှု တိုင်းတာသည့် Benchmark ပေါင်းထည့်ခြင်း (Add a Tool Accuracy Benchmark)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - စနစ်တကျ အကဲဖြတ်ခြင်း

ပေးထားသော အလုပ်တစ်ခုအတွက် အေးဂျင့်သည် မှန်ကန်သော Tool ကို မည်မျှကြိမ်ရေ မှန်ကန်စွာ ခေါ်ယူသည်ကို တိုင်းတာပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. မေးခွန်းများနှင့် မျှော်မှန်းထားသော Tool ခေါ်ယူမှုများ ပါဝင်သော Dataset တစ်ခု ဖန်တီးပါ။
2. မေးခွန်းတစ်ခုစီအတွက် အေးဂျင့်ကို Run ပါ။
3. အမှန်တကယ် ထွက်ပေါ်လာသော Tool စီးဆင်းပုံနှင့် မျှော်မှန်းထားသော စီးဆင်းပုံကို နှိုင်းယှဉ်ပါ။
4. Tool ရွေးချယ်မှုအတွက် Precision, Recall နှင့် F1 တို့ကို အစီရင်ခံပါ။

### စကားပြော အရည်အသွေး အကဲဖြတ်စနစ် ပေါင်းထည့်ခြင်း (Add Conversation Quality Evaluation)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - LLM-as-judge

အေးဂျင့် စကားပြောဆိုမှုများ၏ အရည်အသွေးကို အကဲဖြတ်ရန် LLM ကို အသုံးပြုပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. စံနှုန်းများ သတ်မှတ်ပါ - အကူအညီဖြစ်မှု၊ တိကျမှု၊ လိုရင်းတိုရှင်းဖြစ်မှု၊ ဘေးကင်းမှု။
2. စကားပြောဆိုမှု တစ်ခုစီအတွက် စကားပြောမှတ်တမ်းကို Judge LLM ထံ ပေးပို့ပါ။
3. အကဲဖြတ်ချက်များကို စုဆောင်းပြီး စုစုပေါင်း ရမှတ်များကို တွက်ချက်ပါ။
4. အကဲဖြတ်ချက်များကို အသုံးပြုသူ၏ တုံ့ပြန်ချက်များနှင့် တိုက်ဆိုင်စစ်ဆေးပါ။

## အေးဂျင့်နှင့် Tools စနစ် (Agent and Tooling)

### Code Formatter Tool တစ်ခု ပေါင်းထည့်ခြင်း (Add a Code Formatter Tool)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - Tool ရေးဆွဲထုတ်လုပ်ခြင်း

ရွေးချယ်ထားသော ဖိုင်များပေါ်တွင် Prettier သို့မဟုတ် Biome ကို Run ပေးသည့် Tool တစ်ခု ပေါင်းထည့်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `src/tools/index.ts` ထဲတွင် Tool သတ်မှတ်ချက် အသစ်တစ်ခု ပေါင်းထည့်ပါ။
2. ဖိုင်လမ်းကြောင်း Input ကို စစ်ဆေးအတည်ပြုရန် Zod ကို အသုံးပြုပါ။
3. `run_bash` မှတစ်ဆင့် `prettier --write <file>` ကို Run ပါ။
4. ပြန်လည်စစ်ဆေးနိုင်ရန် ကွာခြားချက် (diff) များကို အသုံးပြုသူထံ ပြသပါ။

### Git Branch Manager တစ်ခု ပေါင်းထည့်ခြင်း (Add a Git Branch Manager)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Git အလိုအလျောက် လုပ်ဆောင်မှု

Git branches များကို ဖန်တီးခြင်း၊ ပြောင်းလဲခြင်းနှင့် ပေါင်းစည်းခြင်းတို့အတွက် Tools များကို ပေါင်းထည့်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `create_branch`၊ `switch_branch`၊ `merge_branch` tools များကို ပေါင်းထည့်ပါ။
2. Branch အမည်များကို Zod ဖြင့် စစ်ဆေးပါ။
3. `run_bash` မှတစ်ဆင့် Git commands များကို Run ပါ။
4. Branch အခြေအနေကို TUI တွင် ပြသပါ။

### Database Query Tool တစ်ခု ပေါင်းထည့်ခြင်း (Add a Database Query Tool)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - ပြင်ပ ဝန်ဆောင်မှု ချိတ်ဆက်ခြင်း

အေးဂျင့်အား Database သို့ တိုက်ရိုက် Query မေးမြန်းခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. ချိတ်ဆက်မှု ပြင်ဆင်ချက် ပါဝင်သော `query_database` tool တစ်ခုကို ပေါင်းထည့်ပါ။
2. Injection မှ ကာကွယ်ရန် SQL queries များကို စစ်ဆေးပါ။
3. ရလဒ်များကို ဇယားပုံစံတကျ ပြန်လည် ပေးပို့ပါ။
4. ဖတ်ရှုခွင့်သက်သက် (Read-only) ဖြစ်စေရန် ခွင့်ပြုချက် အကာအကွယ် ပေါင်းထည့်ပါ။

## LLM နှင့် တုံ့ပြန်ချက် ထုတ်လုပ်ခြင်း (LLM and Generation)

### Multi-Modal စနစ် ထောက်ပံ့မှု ပေါင်းထည့်ခြင်း (Add Multi-Modal Support - Images)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Multi-modal LLM

အေးဂျင့်အား ရုပ်ပုံများကို Vision စွမ်းရည်ပါရှိသော Models များထံ ပေးပို့၍ လေ့လာသုံးသပ်နိုင်စွမ်း ရရှိစေပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. လက်ရှိ Model က Vision ကို ထောက်ပံ့မှု ရှိမရှိ စစ်ဆေးပါ။
2. ရုပ်ပုံလမ်းကြောင်း သို့မဟုတ် URLs များကို လက်ခံနိုင်သည့် `analyze_image` tool တစ်ခု ပေါင်းထည့်ပါ။
3. ရုပ်ပုံများကို Base64 အဖြစ် ပြောင်းလဲပြီး LLM request ထဲတွင် ထည့်သွင်းပါ။
4. LLM ၏ ရုပ်ပုံ သုံးသပ်ချက်ကို TUI တွင် ပြသပါ။

### Streaming Artifacts ပေါင်းထည့်ခြင်း (Add Streaming Artifacts)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - ပိုမိုကြွယ်ဝသော တုံ့ပြန်ချက် ရလဒ်များ

အေးဂျင့်အား စာသားများ ပေးပို့နေစဉ်အတွင်း အဆင့်မြင့် ရလဒ်များ (Code blocks၊ Diagrams၊ Tables) ကို ထုတ်လုပ်ခွင့် ပေးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. တိုက်ရိုက် ထွက်ပေါ်လာသော တုံ့ပြန်ချက်များထဲရှိ Artifact markers များကို စစ်ဆေးပါ။
2. TUI တွင် Code blocks များကို အရောင်မွမ်းမံမှုများ (Syntax highlighting) ဖြင့် ပုံဖော်ပေးပါ။
3. Code artifacts များကို ကူးယူနိုင်ရန် Copy-to-clipboard ခလုတ်များ ပေါင်းထည့်ပါ။

### Model အစားထိုး အသုံးပြုမှု စနစ် ပေါင်းထည့်ခြင်း (Add Model Fallback Chains)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - စနစ်၏ ကြံ့ခိုင်မှု

Provider တစ်ခုခု အလုပ်မလုပ်တော့ပါက သို့မဟုတ် Rate limit မိသွားပါက အလိုအလျောက် အစားထိုး အသုံးပြုမည့် စနစ်ကို ပြင်ဆင်သတ်မှတ်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. အသုံးပြုသူ သတ်မှတ်ထားသော Fallback chains များကို ထောက်ပံ့နိုင်စေရန် `src/llm/fallback.ts` ကို တိုးချဲ့ပါ။
2. Fallback အစီအစဉ်အတွက် CLI/Config အပိုဆောင်း ပြင်ဆင်ချက်များ ပေါင်းထည့်ပါ။
3. စစ်ဆေးပြင်ဆင်နိုင်ရန် Fallback ဖြစ်ရပ်များကို မှတ်တမ်းတင် (Log) ပါ။

## သတင်းအချက်အလက် ရယူခြင်းနှင့် Context စီမံမှု (Retrieval and Context)

### အေးဂျင့်တွင် RAG စနစ် ပေါင်းထည့်ခြင်း (Add RAG to the Agent)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - မှတ်တမ်းအချက်အလက် အခြေပြု Coding

အေးဂျင့်အား မဖြေကြားမီ RAG ကို အသုံးပြု၍ သင်၏ အချက်အလက် မှတ်တမ်းများ သို့မဟုတ် Codebase ကို ရှာဖွေခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. သင်၏ Project မှ စာရွက်စာတမ်းများနှင့် Source code များကို Vector store ထဲသို့ Index လုပ်ပါ။
2. Hybrid search ပြုလုပ်နိုင်သော `search_codebase` tool တစ်ခု ပေါင်းထည့်ပါ။
3. LLM မခေါ်ယူမီ ရရှိလာသော ရလဒ်များကို အေးဂျင့်၏ Context ထဲသို့ ထည့်သွင်းပေးပါ။
4. RAG ပါဝင်မှုရှိသော/မရှိသော အဖြေများ၏ အရည်အသွေးကို နှိုင်းယှဉ်ပါ။

### စကားပြောမှတ်တမ်း အနှစ်ချုပ် စနစ် ပေါင်းထည့်ခြင်း (Add Conversation Memory Summaries)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Context အမြောက်အမြား စီမံခန့်ခွဲခြင်း

Context မပျောက်ပျက်စေဘဲ Tokens ပမာဏကို ချွေတာရန် ရှေးယခင် စကားပြော မှတ်တမ်းများကို အနှစ်ချုပ်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. `src/session/` ထဲတွင် စကားပြော မှတ်တမ်း ပမာဏ သတ်မှတ်ချက် ထက် ကျော်လွန်သွားချိန်ကို စစ်ဆေးပါ။
2. စကားပြော မှတ်တမ်းဟောင်းများကို အနှစ်ချုပ်ရန် LLM ကို ခေါ်ယူပါ။
3. အနှစ်ချုပ်ကို System prompt ၏ ထိပ်တွင် ပေါင်းထည့်ပါ။
4. Token အသုံးပြုမှုနှင့် အဖြေ၏ အရည်အသွေးကို နှိုင်းယှဉ်ပါ။

4. Offline စင့်ခ်လုပ်မှုနှင့် ပေါင်းစည်းမှုများကို စီမံပါ။

### Session မှတ်တမ်းတင်ခြင်းနှင့် ပြန်လည်ပြသခြင်း စနစ် ပေါင်းထည့်ခြင်း (Add Session Recording and Playback)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - Session ပြန်လည်ကြည့်ရှုခြင်း

စစ်ဆေးပြင်ဆင်ရန် သို့မဟုတ် လေ့ကျင့်ရန်အတွက် အေးဂျင့်၏ Sessions များကို မှတ်တမ်းတင်ပြီး ပြန်လည်ပြသခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Tool ခေါ်ယူမှုများ၊ LLM တုံ့ပြန်ချက်များနှင့် အသုံးပြုသူ Input အားလုံးကို မှတ်တမ်းတင်ပါ။
2. မှတ်တမ်းများကို ပြန်လည်ပြသနိုင်သော Format (JSON) ဖြင့် သိမ်းဆည်းပါ။
3. Session ကို အဆင့်လိုက် ပြန်လည်ပြသပေးသည့် `play` command တစ်ခု ပေါင်းထည့်ပါ။
4. အမြန်နှုန်း ထိန်းချုပ်မှုနှင့် အပိုင်းလိုက် ရွှေ့ဆိုင်းမှုများကို ထောက်ပံ့ပေးပါ။

## အခြေခံ အဆောက်အအုံ (Infrastructure)

### Full Stack အတွက် Docker Compose ပေါင်းထည့်ခြင်း (Add Docker Compose for Full Stack)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - တပ်ဆင်အသုံးပြုခြင်း

TUI၊ Daemon နှင့် လိုအပ်သော မှီခိုမှုများကို Run ပေးသည့် `docker-compose.yml` တစ်ခု ဖန်တီးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. CLI အတွက် `Dockerfile` တစ်ခု ရေးသားပါ။
2. CLI ဝန်ဆောင်မှုပါဝင်သော `docker-compose.yml` တစ်ခု ရေးသားပါ။
3. Environment variables စီမံခန့်ခွဲမှုကို ပေါင်းထည့်ပါ။
4. သန့်ရှင်းသော စက်တစ်ခုပေါ်တွင် စမ်းသပ်ပါ။

### Plugin Marketplace ပေါင်းထည့်ခြင်း (Add Plugin Marketplace)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - ဖြန့်ဖြူးခြင်း

အသုံးပြုသူများအား ပြင်ပ Registry မှ Plugins များကို တပ်ဆင်ခွင့် ပေးလိုက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Plugin manifest format တစ်ခု သတ်မှတ်ပါ။
2. Registry API တစ်ခု တည်ဆောက်ပါ။
3. `mtc plugin install <name>` နှင့် `mtc plugin search <query>` များကို ပေါင်းထည့်ပါ။
4. Plugin စစ်ဆေးခြင်းနှင့် အတည်ပြုခြင်းများကို ထည့်သွင်းဆောင်ရွက်ပါ။

### စနစ် စောင့်ကြည့်လေ့လာရေး Dashboard ပေါင်းထည့်ခြင်း (Add Observability Dashboard)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - စောင့်ကြည့်စစ်ဆေးခြင်း

အေးဂျင့် အသုံးပြုမှု၊ Token သုံးစွဲမှုနှင့် အမှားအယွင်း ဖြစ်ပွားမှုနှုန်းများကို ပြသသည့် Dashboard တစ်ခု တည်ဆောက်ပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. အေးဂျင့် Loop တွင် တိုင်းတာမှု ကိန်းဂဏန်းများ ထည့်သွင်းပါ။
2. တိုင်းတာချက်များကို SQLite တွင် သိမ်းဆည်းပါ သို့မဟုတ် Prometheus သို့ ပေးပို့ပါ။
3. Web dashboard တစ်ခု တည်ဆောက်ပါ။
4. အမှားအယွင်း ပမာဏ များပြားခြင်း သို့မဟုတ် ပုံမှန်မဟုတ်သော အသုံးပြုမှုများအတွက် အကြောင်းကြားချက်များ ပေါင်းထည့်ပါ။

## လုံခြုံရေး (Security)

### Prompt Injection စစ်ဆေးသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Prompt Injection Detection)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - လုံခြုံရေး

LLM ထံ မရောက်ရှိမီ Prompt injection ကြိုးပမ်းမှုများကို စစ်ဆေး၍ တားဆီးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. Injection ပုံစံများကို စစ်ဆေးသည့် Input classifier တစ်ခု ပေါင်းထည့်ပါ။
2. အတွေ့အများဆုံး ပုံစံများ - "ignore previous instructions", "you are now DAN"
3. စစ်ဆေးတွေ့ရှိရသော Injections များအတွက် ဘေးကင်းသော အစားထိုး မက်ဆေ့ဂျ်တစ်ခု ပြန်လည်ပေးပို့ပါ။
4. လုံခြုံရေးအရ စစ်ဆေးနိုင်ရန် ကြိုးပမ်းမှုများကို မှတ်တမ်းတင်ပါ။

### ဖိုင်ပြင်ဆင်မှုများတွင် လျှို့ဝှက်ချက်များကို စစ်ဆေးသည့် စနစ် ပေါင်းထည့်ခြင်း (Add Secret Scanning in Edits)

**ခက်ခဲမှု** - Easy | **သဘောတရား** - လုံခြုံရေး

မသိလိုက်ဘဲ ပါဝင်သွားသော လျှို့ဝှက်ချက်များကို မသိမ်းဆည်းမီ ဖိုင်ပြင်ဆင်ချက်များထဲတွင် ရှာဖွေစစ်ဆေးပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. ပြင်ဆင်ထားသော အကြောင်းအရာများကို စစ်ဆေးရန် `src/secrets/` ကို တိုးချဲ့ပါ။
2. အတွေ့များသော လျှို့ဝှက်ချက် ပုံစံများကို တိုက်ဆိုင်စစ်ဆေးပါ (API keys, tokens, passwords)။
3. မသိမ်းဆည်းမီ အသုံးပြုသူအား သတိပေးပါ။
4. ကျော်လွန်ဆောင်ရွက်နိုင်ရန် `--force` flag တစ်ခု ပေါင်းထည့်ပါ။

## အကဲဖြတ်ခြင်းနှင့် စမ်းသပ်ခြင်း (Evaluation and Testing)

### Tool တိကျမှု တိုင်းတာသည့် Benchmark ပေါင်းထည့်ခြင်း (Add a Tool Accuracy Benchmark)

**ခက်ခဲမှု** - Medium | **သဘောတရား** - စနစ်တကျ အကဲဖြတ်ခြင်း

ပေးထားသော အလုပ်တစ်ခုအတွက် အေးဂျင့်သည် မှန်ကန်သော Tool ကို မည်မျှကြိမ်ရေ မှန်ကန်စွာ ခေါ်ယူသည်ကို တိုင်းတာပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. မေးခွန်းများနှင့် မျှော်မှန်းထားသော Tool ခေါ်ယူမှုများ ပါဝင်သော Dataset တစ်ခု ဖန်တီးပါ။
2. မေးခွန်းတစ်ခုစီအတွက် အေးဂျင့်ကို Run ပါ။
3. အမှန်တကယ် ထွက်ပေါ်လာသော Tool စီးဆင်းပုံနှင့် မျှော်မှန်းထားသော စီးဆင်းပုံကို နှိုင်းယှဉ်ပါ။
4. Tool ရွေးချယ်မှုအတွက် Precision, Recall နှင့် F1 တို့ကို အစီရင်ခံပါ။

### စကားပြော အရည်အသွေး အကဲဖြတ်စနစ် ပေါင်းထည့်ခြင်း (Add Conversation Quality Evaluation)

**ခက်ခဲမှု** - Hard | **သဘောတရား** - LLM-as-judge

အေးဂျင့် စကားပြောဆိုမှုများ၏ အရည်အသွေးကို အကဲဖြတ်ရန် LLM ကို အသုံးပြုပါ။

**လုပ်ဆောင်ရန် အဆင့်များ** -

1. စံနှုန်းများ သတ်မှတ်ပါ - အကူအညီဖြစ်မှု၊ တိကျမှု၊ လိုရင်းတိုရှင်းဖြစ်မှု၊ ဘေးကင်းမှု။
2. စကားပြောဆိုမှု တစ်ခုစီအတွက် စကားပြောမှတ်တမ်းကို Judge LLM ထံ ပေးပို့ပါ။
3. အကဲဖြတ်ချက်များကို စုဆောင်းပြီး စုစုပေါင်း ရမှတ်များကို တွက်ချက်ပါ။
4. အကဲဖြတ်ချက်များကို အသုံးပြုသူ၏ တုံ့ပြန်ချက်များနှင့် တိုက်ဆိုင်စစ်ဆေးပါ။
