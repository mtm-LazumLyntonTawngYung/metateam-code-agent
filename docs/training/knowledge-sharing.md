# Knowledge Sharing

Guides for team leads and advocates to promote mtc adoption within their teams.

---

## Team Lead Checklist

- [ ] All engineers on your team have completed the [Onboarding Guide](../internal/onboarding.md)
- [ ] Team projects have `.mtc/` configuration committed
- [ ] CI pipeline includes `mtc review` for PRs
- [ ] At least one team member can write MCP plugins
- [ ] Team has identified 3-5 high-value use cases for mtc

## Suggested Use Cases by Team

### Backend Engineering

- API endpoint scaffolding from OpenAPI specs
- Database migration generation
- Refactoring legacy services
- Writing integration tests

### Frontend Engineering

- Component scaffolding from Figma designs
- State management refactoring
- Migration between frameworks (e.g., Angular → React)
- Accessibility audits

### DevOps / Platform

- Infrastructure-as-code generation
- CI/CD pipeline refactoring
- Dockerfile optimization
- Monitoring dashboard creation

### Data Engineering

- ETL pipeline code generation
- Query optimization suggestions
- Data validation rule creation
- Schema migration scripts

## Office Hours Format

Weekly 30-minute sessions:

1. **Demo (10 min):** Showcase a new feature or advanced workflow
2. **Q&A (10 min):** Open questions
3. **Show & Tell (10 min):** Team members share what they built with mtc

## Newsletter Tips

Monthly engineering newsletter should include:

- "MTC Tip of the Month" — one specific workflow or trick
- New plugin or agent releases
- Usage statistics (sessions, tokens saved, etc.)
- Spotlights on teams using mtc effectively

## Advocates Program

Power users can become **MTC Advocates**:

- Early access to new features
- Direct line to Platform Lead
- Recognition in the engineering newsletter
- Responsibility: mentor 2-3 new users per quarter
